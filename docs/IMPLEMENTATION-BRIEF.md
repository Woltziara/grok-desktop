## 用户真正想要的产品

Grok Desktop 是面向完全不写代码的使用者的工作与对话入口：还原真实问题、找材料、使用工具、生成可用成果、接着工作，用户能随时插话纠正。已经投入的材料和判断不能因为换对话、换账号、换机器而凭空丢失。

继续使用 Electron + React + ACP，接入本机已安装的官方 Grok Build；不迁入 Tauri，不重新实现智能体。智能体、模型、工具执行、技能、MCP、权限和工作树优先复用官方已有能力。桌面负责人可见、可控、可恢复的适配。不要把此应用扩展成通用工作流平台或多智能体指挥台。

界面维持“对话客厅”：左边项目/最近，中间对话，右边仅在需要查看产物时出现。打开就能说，不先强迫选文件夹；默认不展示文件树、终端、Git 状态和一排工程开关。用户输入右侧短气泡，回复是左侧阅读正文。Paper & Ink、状态色及许可证边界见 docs/INTENT-LOCK.md。该文档的早期实现顺序/模块示例属于历史手段，不能凌驾于本次完整任务；其中明确用户冻结的产品形态、配色和技术边界继续保留。

Grok 账号只代表模型服务身份；本机项目、会话、个人工具及资料属于使用者。切号或登出不能清空这些资料，也不能退出不相关的 GitHub、邮箱或其他工具。

## 需要完整兑现的用户行为

1. **项目与会话组织。** 项目内新建、项目的新增入口、最近列表，以及把对话拖到另一个项目。跨项目归属变化必须有真实、一致的工作目录语义，保留会话历史、草稿、附件和阅读位置，并保护正在执行的回合及其他会话。若官方会话目录不可直接搬迁，选择能满足上述结果的兼容做法并说明语义，不以只改标签冒充真实归属迁移。
2. **持续可靠的对话。** 草稿、文本引用、大图片、文件和文件夹附件按会话隔离；发送失败、会话切换、关闭与重启后可恢复，存储失败须可见。旧历史与实时尾部合并不能覆盖新消息；去重依据真实事件身份，不能吞掉相同文本的不同输入。阅读锚点不抢用户滚动；切换界面不终止其他后台工作。
3. **插话、排队和取消。** 空闲 Enter 发送；忙碌 Enter 在当前回合安全节点插入；“稍后”进入下一轮 FIFO；Cmd/Ctrl+Enter 取消当前回合后发送。取消及时且只影响目标会话。队列编辑、移动、删除、失败恢复一致；插话不重启整轮 Worked-for 计时。最终只保留一条真实发送/ACP 协议路径，避免两套实现争抢。
4. **工作认识的持续与纠正。** 用户明确选择业务对象后，可以跨会话带入、查看、纠正、撤回和关闭。来源、用户原话、背景、偏好、决定、模型推断、未知、执行结果不能混为一谈；纠正要生效，撤回不能悄悄复活。插话、自动压缩、重试、取消和迟到结果都要纳入生命周期，不能漏掉本轮纠正或写到错误对象。未选择对象的普通请求原文直通，不默认绑定业务，不自动探针。现有真实业务资料在本机独立数据目录，GitHub 没有包含；正式源码/安装包不得种入真实业务样本。与原生 Grok memory 的关系应减少重复与冲突；不要因名称相似就未经验证迁移现有知识数据。
5. **计划、问答和权限。** 计划模式、批准并附意见、文件夹信任、权限请求、问答/补充材料请求，经主进程、界面和真实 ACP 接通；重载和切换会话不丢失、不串到其他会话。批准意见送入正确后续路径，不隐式扩张权限。
6. **Preview 可真正使用。** 独立的持久登录分区，用户登录一次后重启仍保留其本站会话；结构化定位/输入，按需要兼容 DOM、网络、iframe、上传和下载。动作、页面及截图必须有正确的窗口与会话归属；关闭/重开、主进程退出和过期请求都安全。只操作 Preview 自身的页面与登录，不读/拷 Chrome、Edge、Codex 的 Cookie、密码或钥匙串。当前 loopback 随机 CDP 端口与正常绑定是兼容事实，不能为方便开放任意 origin 或接管无关浏览器。
7. **应用内网页 Pro 开发闭环。** Grok Desktop 能通过自身正常接入的能力向真实网页 GPT Pro 交办，等待/读取交付，接回源码、本机修改、测试、返修，最后留下可运行产物和报告。它应是现有 Grok、技能/MCP、Electron/Playwright 能力的合理组合。不要只造几个工具名、打开网页或读 GitHub 就宣布闭环完成；不要通过模拟 Pro 返回或将答案写进正式路径伪装成功。headless 进程不会自动继承桌面的 Preview MCP，这个接缝必须可用且可核实。Codex 的右侧浏览器面板是本次外部交办通道，不是额外强制的 Grok 产品界面设计。
8. **跨机器接续与唯一版本。** 目标是本机与 MacBook Pro 使用同一源码主线及同一可校验应用版本。已有业务会话和资料要有明确的同步范围、方向、备份与冲突处理；默认本机向僚机发出已确认版本。工作认识跨机器可接续，不能用文件修改时间裁决哪条业务判断正确，也不能静默覆盖并发纠正。你可选择简单、可靠且可解释的机制，不强制 Codex 某个方案。凭据/邮箱/OAuth 迁移不在本次包内，不能随资料复制。源码版本不再通过 mtime rsync 回灌旧副本。
9. **可交付、可追溯。** 一个完整可构建版本，说明从旧数据/应用到新版本的恢复与升级路径；不保留能被误启动为另一套产品的旧源码或第二套协议实现。保护用户原件和非本任务成果。最终源码、包、进程和用户路径应能对应；正式 macOS 安装与另一机器部署由本地验收完成后执行，不要求你在不存在的设备上伪造部署。

## 源码基线与已知缺口

本次分支起点是当前统一工作树，基于 main 的 9fdbba1ababf62f404df7fbfa4fda9be5a42f566，版本 1.4.2-unified.1。已经将多个历史来源整合成项目根的一份仓库，旧的 grok-desktop 子目录和 Tauri/参考副本已归档移除。主线是公开 origin/main 的正常后裔，私有旧开发历史没有混入其祖先；公开 Git 祖先只有已清理的本项目主线。不要恢复旧嵌套目录或平行代码树。

本地还有 package.json 的 electronDist 指向 node_modules/electron/dist 的未提交改动，已经包含在本次分支。这是本机断网构建恢复的事实，可以为可靠、可移植构建改进，但不得无意丢掉其解决的完整 SDK 来源问题。

以下是已观察到的缺口，不是全部范围，也不是限定修法：

- shared/workspace-org.mjs 明确未实现跨项目搬会话；AppSidebar 的 DndContext 目前只排序项目。对话换归属是缺失功能。
- electron/acp-client.mjs 的 interject() 绕过工作认识原话 inbox。忙碌时的用户纠正没进入该轮来源集合。修复须覆盖接受的插话、重复 interjectionId、取消/失败后的待处理原话、对象切换和迟到输出；避免第二次包装/消费整个 turn。
- electron/preview-api.mjs 的 dispatchPreviewApi 在每个含 req.owner 的请求上调用 claimPreviewOwner。B 会话的 snapshot/click/close 可把 A 的单例 Preview 抢为己有，随后用户“发截图”发到 B。应区分有权打开/显式转交与后续操作，核实有效归属并安全处理过期/缺失 owner。
- 启动错误展示仍可把配置解析错误误作 Session expired，且直接展示重复 ANSI 日志；应给人可理解的真实原因和恢复办法。
- 网页 Pro 完整闭环、真实账号跨重启、工作认识跨机同步、统一包全部真实交互及最终两机部署尚未验收。不能把 helper 单测通过等同于这些结果。
- 已撤销的一条审查误报：applyCommitFromAssistantText 内部本来就强制 fromModel:true，不存在“调用者没传这个参数所以能绕过”的已证漏洞。不要重复修这个假问题。
