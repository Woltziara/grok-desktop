# Grok Desktop 意图锁定

**状态：已锁定。未得到用户当面改口之前，不得漂移。**  
锁定日期：2026-08-31  
锁定原因：先定意图和组合方案，再执行。防止做到一半变成 Codex 工作台，或从零重做一套界面。

本文同时给人和后续代理看。改主界面之前必须先读完。若某次改动和本文冲突：**停下来问用户**，不要自行圆过去。

---

## 一、为谁做

使用者是**完全不写代码的人**。

工作是把客户的真实问题、责任结构、AI 和业务结果重新对齐，直到它能运行、能验证、下一单少依赖临场救火。不是写代码、改仓库、看 diff。

因此：主界面必须是给「审案子的人」用的客厅，不是给工程师用的工作室。

---

## 二、这是什么产品（一句）

Grok Desktop 仍然只是 **Grok Build 智能体的桌面壳**。

- 大脑、登录、技能、MCP、工具：继续用已经装好的 `grok`，不另做一套智能体。
- 本仓库继续是 Electron + React，继续走 ACP。
- 要改的是**人打开窗口后看见什么、先碰到什么**。

不另起炉灶。不换成 Tauri。不重写 agent。

### 人的家 vs Grok 账号（2026-09-02 锁定）

Grok 账号只是接进来的大脑（谁在给模型付钱、左下角头像上的名字）。  
**人的家**绑在这台电脑上，不跟 Grok 账号走：

| 人的家（必须同一套） | 会随 Grok 账号变的 |
|----------------------|-------------------|
| 左边栏的 **项目** 和 **最近**（同一批案子，不按账号各做一份） | 左下角头像上的 Grok 名字 / 邮箱 |
| GitHub（本机已登录的那个身份，例如 `gh`、GitHub MCP） | 模型额度、团队、能否连上大脑 |
| 邮箱和其他个人工具（飞书、邮件 MCP 等） | |
| 技能、插件、MCP 清单与它们已经记下的登录 | |

换一个 Grok 账号再登录：**不许**清空侧边栏、**不许**退出 GitHub / 邮箱、**不许**按新账号另起一套案子。  
登出 Grok 只摘掉大脑；案子仍在磁盘上，个人工具仍是原来的登录。  
禁止按 Grok 的 `user_id` / 邮箱给侧边栏、会话列表、MCP 凭据做分柜。

## 三、视觉北针（公论）

对不会写代码的人，公论是 **Claude Desktop 那种聊天客厅**，不是 Codex 那种代码工作台。

三栏含义（冻结）：

| 位置 | 人看到的 | 不是 |
|------|----------|------|
| **左，窄** | 案子 / 最近对话 | 磁盘目录、大按钮、账号卡、诊断信息 |
| **中，最宽** | 正在还原现场的对话 | 代码编辑器、终端、文件树 |
| **右，默认没有** | 正在生效的那一页（问题稿 / 责任 / 试验 / 待确认） | 常开的项目文件树 |
| **输入框** | 贴在中间底部，圆角、安静；模型和权限藏在框内小标签里 | 顶栏一排药丸按钮 |

打开软件的第一眼（冻结）：

> 中间一个名字，下面一个输入框。可以直接开始说这件事。  
> 左边是最近几案。右边空着。  
> 只有出现「你必须盯着看的一页」时，右边才打开。

账号、设置、退出：只在左下角头像里。

### 对话轮次怎么分（2026-08-31 补锁）

不要靠「你 / GROK」小字，也不要两边都做成短信气泡。成熟产品已经收成同一套：

- **你说的话**：靠右、深色圆角气泡，宽度大约占阅读栏的七成，短句更短。
- **回复**：靠左、不装进气泡，占满阅读栏，列表 / 引用 / 代码按正文排。
- **依据**：ChatGPT 的用户气泡、Claude「提问在右、回答在左」、Codex 同一结构。两边都装气泡会压扁长回复；两边都当正文，人就要用肉眼找谁在说话。

### 底座：颜色、字体、排版（2026-08-31 补锁）

权威来源：`~/.config/waveterm/Paper-Ink-浅色外观方案.md` 以及同目录的 `settings.json` / `termthemes.json` / `backgrounds.json`。不要再从旧的 `claude-warm` 或 `custom.css` 往回抄。

| 角色 | 值 | 用法 |

| 暖墨 | `#57504A` | 正文 |
| 深墨 | `#3B3733` | 标题、粗体 |
| 辅助灰 | `#8A8075` | 次要说明 |
| 强调 | `#0E7490` | 唯一强调：主按钮、选中、光标感。不是蓝，不是砖红。 |
| 错误 | `#B91C1C` | 只给错误 |

红只表示错误。强调色独占。不要把成功涂成红，也不要把 iOS 蓝、旧紫色当主色。

### 对话状态色（2026-08-31 用户改口）

纸墨纪律只管**壳**：窗口、侧栏、输入框、选中、主按钮。强调仍是青灰 `#0E7490`。

对话里「谁在干什么」用 **GrokDay 原色**，只涂状态行，不涂正文：

| 在干什么 | GrokDay 槽 | 色 |
|---------|------------|-----|
| 正在想 / Recap | `accent_thinking` | `#7D4BC6` |
| 工具正在跑 | `running` | `#0082AA` |
| 这一轮做完（Worked for） | `accent_success` | `#378E23` |
| 失败 | `accent_error` | `#CD3048` |

收起的工具行仍是浅墨，避免整页变绿。不要因此把侧栏、按钮、标题涂成品红。

### 对话排版的版本答案（不要再靠截图肉眼对）

成熟实现已经定型，不要自己发明：

1. **对话骨架**用 ChatGPT / Claude / Codex 同一套：你的话靠右短气泡，回复靠左当阅读栏，不是两张对称卡片。
2. **Markdown**用 GitHub 的定型样式（`sindresorhus/github-markdown-css`，MIT）。列表、引用、行内代码、标题都走这份，不要把它们淡成和正文一个颜色。
3. 颜色仍套 Paper & Ink。改 Markdown 观感时，改映射层 `src/styles/markdown-paper-ink.css`，不要再手写一套列表样式。

### 不要再靠截图肉眼对（2026-08-31 补锁）

客厅外观已经锁死。TUI 是终端，桌面是客厅，**不要像素对齐 TUI 截图**。

要对齐的是 **TUI 已经写进磁盘的行为**：

- 对话正文：`~/.grok/sessions/.../updates.jsonl` 里的 `sessionUpdate` 种类（Thinking / Recap / Worked for / 工具…）
- 左边列表：TUI `/resume` 同一套索引（`summary.json` 的 `generated_title`，没有标题就用第一句人话）

点开旧对话 **不得** 把它挪到最上面。排序只看最后一句真话，不看最后一次点开。没说过话的空壳（只有 hook、没有 user/assistant）不进列表，也不许显示英文 `(no summary)`。

以后缺一块，先在 jsonl / `summary.json` / `~/.grok/docs/user-guide/` 里对种类，再补桌面。不要再让用户对着两张图找茬。

## 四、主界面永远不许出现的东西

这些可以存在于设置、次要入口、或工程师以后用的角落，**不得作为主界面默认内容**：

- 整盘文件树、Git 状态、工作树、终端
- 顶栏一排 Perms / Effort / Compress / Connected
- 大块「打开项目」「退出登录」
- Token、费用、Session ID、二进制路径当主信息
- 每个工具贴一个 TOOL / THINKING / completed 大徽章
- 蓝、紫、黄、绿同时抢戏

主界面上人需要一直知道的，最多三件，而且用人话：

1. AI 现在可以做什么、不能做什么（例如：可以查依据，不能对外承诺）
2. 这件事有没有必须停下的理由
3. 下一动是谁的

## 六、怎样算没有漂

能参考界面和结构，就参考。能看设计原则，就看设计原则。

```

  Electron 窗口 + ACP + 登录 + 会话 + 权限审批 + Preview + 设置
```

## A. 原封保留（不要重做）

来源：**本仓库 Grok Desktop**

| 零件 | 为什么留 |
|------|----------|
| Electron 主进程、ACP 连接、`grok agent stdio` | 这就是产品的大脑接口 |
| 浏览器登录 / 退出 / API key | 已经能用 |
| 会话列表、恢复历史 | 左边「案子」的底下就是它 |

## B. 主骨架：从 grok-app 组合（最像、且许可证允许）

来源：[RongleCat/grok-app](https://github.com/RongleCat/grok-app)  
许可证：**MIT**（可以对照结构在我们自己的 React 里重写，不整仓复制）  
它和咱们是同一类产品：本地 `grok` + 桌面工作台。空状态已经是「中间大标题 + 漂浮输入框」。

对照着搬的是**结构，不是 Tauri 工程**：

| grok-app 里的部分 | 组合进我们哪里 | 人看到的结果 |
|-------------------|----------------|--------------|
| `AppWorkbench` / `WorkbenchMain` | `App.tsx` 的主框架 | 左会话、中对话、右按需 |
| `WorkbenchSidebar` + `SidebarSessionRow` | 替换现在的 `AppSidebar` 气质 | 左边只是名单，没有大按钮和诊断 |
| `AccountPanel` 收在左下 | 替换侧栏中部的账号卡 / 退出 | 头像里才有退出和设置 |
| `WorkbenchComposerShell` + 框内菜单（项目 / 模型 / 权限） | 替换 `Composer` + 拆掉 `ChatTopbar` 药丸 | 输入框自己带着小标签 |
| `WorkbenchChatStage` 的空状态 | 替换「必须先打开项目」的 `WelcomeView` 主路径 | 打开就能说 |
| `WorkbenchResourcesAside` 的「需要才出现」 | 右边侧拉窗：这次对话生成的文件，点开就能试；HTML 在窗里打开 | 右边不是文件树 |

**明确不从 grok-app 拿来的：** 桌面宠物、十一路即时通讯桥、看板、自动换皮商城、中转供应商大市场。那些是另一款产品。

## H. 当时的组合顺序（历史）

得到你点头之后，才按这个顺序做。每一步都必须仍满足「第三节视觉北针」：

1. **空状态 + 输入框**：打开就能说；模型 / 权限进输入框内；顶栏药丸消失。
2. **左边变安静**：只留案子/会话名单；账号进左下角；诊断离开主界面。
3. **右边默认关掉**：文件树不再当默认；有「一页纸」时才打开。
4. **对话变成人话**：工具过程收成短状态，不再用大徽章当主角。
5. **一种强调色、浅色客厅为默认**（可保留深色，但不以 Codex 深色编辑器为默认主页）。

做完用你的标准验收：不写代码的人打开，会不会觉得这是给自己用的。
